COPILOT CHAT MODE SELECTION - SOLUTIONS
========================================

---

TASK 1: UNDERSTAND AUTHENTICATION FLOW

Answer: ASK mode

Why:
- Goal is exploration, not code generation
- Need to understand existing architecture before changes
- No code modifications required
- Multiple files and concepts need explanation

Recommended Prompt:
@workspace How does authentication work in this app? Explain the middleware chain. Which files are involved?

Follow-up:
What would I need to modify to add a new authentication provider?

Key Learning: Use ASK when you need to understand before you act

---

TASK 2: FIX MISSING INPUT VALIDATION

Answer: EDIT mode

Why:
- Single file (backend/contact-routes.ts)
- Clear, specific requirement
- Low risk, isolated change
- Small scope - one function

Approach:
1. Open backend/contact-routes.ts
2. Select POST /contacts route handler
3. EDIT mode: "Add validation to ensure contactUserId is not the same as authenticated user's ID. Return 400 error with message 'Cannot add yourself as a contact' if they match."

Key Learning: Use EDIT for small, focused, single-file changes with clear requirements

---

TASK 3: IMPROVE ERROR HANDLING

Answer: ASK + EDIT (iterative)

Why:
- Unsure of best practices for this codebase
- Need guidance first, then implementation
- Single file but multiple functions
- Want consistency with existing patterns

Approach:
Phase 1 - ASK: "@workspace What error handling improvements should I make to backend/bankaccount-routes.ts? What patterns are used elsewhere?"
Phase 2 - EDIT: For each route, add try-catch with proper status codes
Phase 3 - VALIDATE: Run yarn types, test endpoints

Key Learning: Combine modes when you need guidance before implementation

---

TASK 4: ADD REQUEST RATE LIMITING

Answer: ASK → EDIT → VALIDATE

Why:
- Unfamiliar territory (existing packages unknown)
- Higher risk (affects API traffic)
- Multi-step process
- Need to validate dependencies and config

Approach:
Step 1 - ASK: "@workspace What's the best way to add rate limiting? Are there packages already installed?"
Step 2 - EDIT: Create backend/rate-limiter.ts with middleware
Step 3 - EDIT: Apply middleware to transaction route
Step 4 - VALIDATE: Install packages if needed, test

Key Learning: Use ASK → EDIT → VALIDATE for unfamiliar, risky changes

TASK 6: REFACTOR DATABASE QUERY FUNCTIONS

DECISION FRAMEWORK

Use ASK when:
- Need to understand code/architecture
- Requirements unclear
- Investigating bugs
- Exploring options
- Understanding existing patterns

Use EDIT when:
- Single file, single function change
- Requirements crystal clear
- Low risk, isolated change
- Know exactly what to do
- Quick fix or small enhancement

Use ASK + EDIT when:
- Need guidance on best practices
- Iterative improvements
- Want to validate approach first
- Learning while coding

Use ASK → EDIT → VALIDATE when:
- Unfamiliar technology/pattern
- Higher risk changes
- Need to research dependencies
- Security-sensitive code
- Performance-critical changes

Use AGENT when:
- Multiple files need changes
- Full-stack features
- Refactoring across codebase
- New component with related files
- Complex feature with many parts
- Systematic changes following pattern

---

KEY PRINCIPLES

1. Start with ASK if unsure
2. EDIT for focused changes
3. AGENT for coordination
4. Validate risky changes
5. Don't over-use Copilot
6. Combine modes as needed
