BUG #1: AVATARS NOT DISPLAYING

Answer: ASK → EDIT → AGENT

Phase 1: Investigation (ASK Mode)

Why ASK first:
- Issue affects multiple components
- Root cause unclear (data/URL/rendering)
- Need to trace data flow
- Want to understand where avatars used

Investigation Prompts:
1. "@workspace Where are user avatars displayed? Show me all components that render avatars."
2. "@workspace How are avatar URLs stored and retrieved? Show me User model and avatar generation."
3. "@workspace I see avatars use dicebear.com API. Show me where URLs created. Has API endpoint changed?"

Root Cause:
Old URL: https://avatars.dicebear.com/api/human/{id}.svg (deprecated)
New URL: https://api.dicebear.com/7.x/avataaars/svg?seed={id}
External API changed!

Phase 2: Fix (EDIT Mode)

Why EDIT:
- Fix in one location: scripts/seedDataUtils.ts
- getUserAvatar function needs update
- Small, focused change

Steps:
1. Open scripts/seedDataUtils.ts
2. Locate getUserAvatar function (line ~113)
3. Select function
4. EDIT: "Update to use new dicebear API v7. Change from: https://avatars.dicebear.com/api/human/{identifier}.svg to: https://api.dicebear.com/7.x/avataaars/svg?seed={identifier}"

Expected Change:
export const getUserAvatar = (identifier: string) => {
  return `https://api.dicebear.com/7.x/avataaars/svg?seed=${identifier}`;
};

Phase 3: Validation (AGENT Mode)

Why AGENT:
- Need to regenerate database with new URLs
- Verify avatars across all components
- Add tests to prevent future breaks

Validation Prompt:
"I've updated avatar URL generator. Now: 1. Regenerate database seed with new URLs 2. Verify avatars in NavDrawer, TransactionItem, TransactionDetail, UserListItem 3. Add test to verify URLs valid"

Manual Validation:
yarn db:seed
yarn dev
Check: navigation drawer, transaction list, transaction details, user selection

Key Learning:
✓ ASK discovered root cause (API change)
✓ EDIT applied surgical fix
✓ AGENT coordinated validation

Bug Type: External API change
Difficulty: Medium

BUG FIXING BEST PRACTICES

1. Always Investigate First (non-obvious bugs)
   - Use ASK to understand system
   - Trace data/code flow
   - Identify all affected components

2. Apply Surgical Fixes
   - Use EDIT for targeted changes
   - Don't refactor while fixing (unless necessary)
   - Keep changes minimal and focused

3. Validate Thoroughly
   - Test exact scenario from bug report
   - Test edge cases and variations
   - Ensure fix doesn't break other features
   - Add regression tests

4. Mode Selection Logic:
   Root cause obvious? → YES → EDIT to fix
                      → NO → ASK to investigate
                           → Single file? → EDIT
                           → Multi-file? → AGENT

5. Common Bug Patterns:
   - UI bugs → Usually EDIT (CSS/component)
   - Data bugs → ASK (trace flow) → EDIT (fix query/transform)
   - API bugs → ASK (error analysis) → EDIT (fix endpoint)
   - State bugs → ASK (understand sync) → EDIT/AGENT (fix state)

---

KEY TAKEAWAYS

1. ASK mode is debugging partner - understand before fixing
2. EDIT mode for surgical strikes - precise fixes in known locations
3. AGENT mode for complex fixes - multi-file changes and testing
4. Always validate - test bug scenario and related functionality
5. Add regression tests - prevent bug from returning
