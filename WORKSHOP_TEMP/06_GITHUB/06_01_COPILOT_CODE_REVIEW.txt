GITHUB COPILOT CODE REVIEW
===========================

WHAT IS COPILOT CODE REVIEW?

GitHub Copilot offers powerful code review capabilities at two levels:
- Local Code Review: Review changes in VS Code before committing
- GitHub PR Review: Automated code review on Pull Requests

This module covers:
- Setting up code review prompts and instructions
- Using VS Code "Review and Comment" feature
- Reviewing all local changes with chat
- Configuring GitHub Copilot as automatic PR reviewer
- Interacting with Copilot's review comments

---

EXERCISE 1: LOCAL CODE REVIEW

TASK 1.1: CREATE CODE REVIEW CUSTOM INSTRUCTIONS

Goal: Set up project-specific code review guidelines for Copilot.

Steps:
1. Create the directory if it doesn't exist:
   ```bash
   mkdir -p .github
   ```

2. Create or update `.github/copilot-instructions.md` with code review prompts:

Add the following content:

```markdown
# Code Review Guidelines

When reviewing code in this project, check for:

## Security
- No hardcoded credentials, API keys, or secrets
- Proper input validation and sanitization
- No SQL injection or XSS vulnerabilities
- Secure authentication checks

## Code Quality
- Use `const` or `let` instead of `var`
- Use strict equality (=== and !==)
- Proper TypeScript types (no `any` unless justified)
- Remove debug console.log statements before committing
- Remove TODO/FIXME comments or create issues for them
- Delete unused/dead code

## Project Patterns
- Follow existing patterns in `backend/transaction-routes.ts`
- Use express-validator for input validation
- Implement proper error handling with try-catch
- Return appropriate HTTP status codes
- Add JSDoc comments for public functions

## Testing
- Consider edge cases and error scenarios
- Suggest unit test cases for new functions
```

3. Save the file and commit the instructions (optional):
   ```bash
   git add .github/copilot-instructions.md
   ```

Questions:
- Why set up custom instructions before reviewing?
- How do project-specific guidelines help Copilot?
- What other rules would you add for this project?

- Detailed issues found in each file
- Specific suggestions with code examples
- Priority ranking of issues

Alternative Prompt (simpler):

```

Alternative Prompt (security focused):
```

EXERCISE 2: GITHUB PR CODE REVIEW

TASK 2.1: CONFIGURE GITHUB COPILOT AS PR REVIEWER

Goal: Set up GitHub repository to automatically request Copilot reviews on PRs.

Prerequisites:
- Repository admin access
- GitHub Copilot for Business or Enterprise subscription

Steps:
1. Go to your repository on GitHub.com

2. Navigate to Settings → Rules → Rulesets

3. Click "New ruleset" → "New branch ruleset"

4. Configure the ruleset:
   - Name: "Copilot Code Review"
   - Enforcement status: Active
   - Target branches: Add target → Include default branch (main/master)

5. Add rule: "Require code review from Copilot"
   - Check "Require a pull request before merging"
   - Enable "Require review from Code Scanning" or look for Copilot review option

6. Alternative: Repository Settings → Code review assignment
   - Enable "GitHub Copilot code review"
   - Set to automatically request reviews

7. Save the ruleset

Note: The exact UI may vary. Look for:
- Settings → Code review
- Settings → Rules → Rulesets
- Pull request settings

Questions:
- What's the difference between required and optional Copilot review?
- Can Copilot block merge, or only comment?
- How does this integrate with human reviewers?

BEST PRACTICES

For Local Review:
- Set up project-specific review instructions
- Review before committing (shift-left quality)
- Use "Review and Comment" for focused analysis
- Use #get_changed_files for comprehensive review
- Use capable models (Claude Sonnet 4, GPT-4o) for better analysis

For PR Review:
- Enable automatic Copilot review in repository settings
- Don't ignore Copilot comments - address or justify
- Use @copilot mentions to discuss, not dismiss
- Combine Copilot review with human reviewers
- Fix issues in dedicated commits for clear history

General Tips:
- Customize review instructions per project
- Treat Copilot review as first pass, not final authority
- Security issues flagged by Copilot require human verification
- Use review feedback to improve coding habits

COMPARISON: LOCAL VS PR REVIEW

| Aspect           | Local Review              | PR Review                   |
|------------------|---------------------------|-----------------------------|
| When             | Before commit             | After push                  |
| Where            | VS Code                   | GitHub                      |
| Trigger          | Manual                    | Automatic (if configured)   |
| Visibility       | Only you                  | Team can see                |
| Iteration        | Immediate                 | Requires push               |
| Best For         | Quick feedback            | Team collaboration          |
| Integration      | Personal workflow         | CI/CD pipeline              |

Recommendation: Use both! Local review for quick fixes, PR review for team visibility.

TROUBLESHOOTING

"Review and Comment" not appearing:
- Ensure GitHub Copilot extension is installed and active
- Check Copilot is authenticated (status bar icon)
- Restart VS Code if recently installed

Copilot not reviewing PR automatically:
- Verify ruleset is configured and active
- Check repository has Copilot code review enabled
- Ensure PR is to a protected/targeted branch
- Verify GitHub Copilot subscription level supports PR review

@copilot mentions not getting responses:
- Ensure Copilot PR review is enabled for repository
- Check mention is exactly "@copilot" (case-sensitive)
- Wait a few minutes - responses may be delayed
- Verify no service outages on GitHub Status

MCP tools not working:
- Check GitHub MCP server is installed (04_01_GITHUB_MCP.txt)
- Verify Personal Access Token is valid
- Ensure token has `repo` scope

KEY LEARNINGS

1. Custom Instructions Improve Review Quality
   - Project-specific guidelines help Copilot understand context
   - Reduces false positives and irrelevant suggestions

2. Shift-Left with Local Review
   - Catch issues before they reach PR
   - Faster feedback loop
   - Cleaner commit history

3. Automated PR Review Scales
   - Consistent first-pass review
   - Doesn't get tired or busy
   - Good for catching common issues

4. Interaction Makes It Better
   - @mentioning Copilot continues conversation
   - Explain context Copilot might miss
   - Get alternative suggestions

5. Combine with Human Review
   - Copilot catches patterns, humans catch logic
   - Use Copilot for consistency checks
   - Reserve human time for complex decisions
