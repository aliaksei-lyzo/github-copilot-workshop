Chat Modes in GitHub Copilot

Master the three interaction modes: Ask, Edit, and Agent for different development tasks.

🎯 Learning Objectives

  • Understand when to use each chat mode
  • Practice code exploration with Ask mode
  • Make targeted edits with Edit mode
  • Build multi-file features with Agent mode
🔄
Three Chat Modes:
  • Ask Mode (@workspace) - Questions and exploration
  • Edit Mode - Code changes with preview
  • Agent Mode - Multi-step autonomous tasks
0.1

Comment Autocomplete - Generate Validation Function

Task: Create a reusable validation function for transaction amounts.

📄
File: src/components/TransactionCreateStepOne.tsx
Navigate to line 50 (below existing validation)
Type a comment describing validation function
Wait for Copilot suggestion
Press Tab to accept
Expected Result
Complete function implementation from comment
▶ 🔮 Hint
Try: // Function to validate transaction amount is between min and max values

Inline Chat - Add Error Handling

Task: Add robust error handling to the transaction creation endpoint.

📄
File: backend/transaction-routes.ts
Select the POST /transactions endpoint function (entire function body)
Press Cmd+I (Mac) or Ctrl+I (Windows)
Request error handling addition
Expected Result
Error handling wrapped around database operations
▶ 💬 Prompt 
Add try-catch error handling for database failures

Ask Mode - Explore Authentication

Task: Need to modify auth - first understand how it works.

Open Chat panel
Ask about authentication implementation
Review response and identified files
Expected Result
List of auth-related files and flow explanation
▶ 💬 Prompt 
@workspace How is authentication implemented in this application? Which files are involved?

Ask Mode - Trace Transaction Flow

Task: Need to add transaction validation - first understand the existing flow.

Open Chat panel
Ask about transaction creation flow
Identify the sequence: component → API → database
Expected Result
Step-by-step explanation of transaction lifecycle
▶ 💬 Prompt 
@workspace Where is the transaction creation logic? Explain the flow from user action to database.

Agent Mode - Implement Transaction Search

Task: Users need to search transactions by description keyword.

Open Agent mode
Provide complete search feature requirements
Let Agent create backend endpoint, search component, and integrate with list
Expected Result
Search input in UI, backend /search endpoint, Fuse.js integration
▶ 💬 Prompt 
Implement a search feature for transactions that:
1. Adds a search endpoint in the backend that searches by description
2. Creates a search input component
3. Updates the transaction list to support search
4. Uses the existing Fuse.js library

Keep current display logic intact.
6

Agent Mode - Build CSV Export Feature

Task: Add ability for users to download transaction history as CSV.

Open Agent mode
Describe complete CSV export requirements
Review multi-file changes (backend route, UI button, download logic)
Expected Result
Export button in UI, backend /export endpoint, CSV download functionality
▶ 💬 Prompt 
Add the ability to export transactions to CSV format:
1. Create a backend route that generates CSV from transactions
2. Add an export button to the transaction list
3. Trigger download of CSV file when clicked
4. Include transaction date, amount, sender, receiver, and description

Use the existing transaction filtering logic.

🏆 Challenges

★

Challenge 1: Bug Investigation

Task: Users report validation errors - find and fix bugs.

Use Ask mode to find validation bugs
Use Edit mode to fix identified issues
Verify fixes don't break existing functionality
Expected Result
2-3 bugs identified and fixed
▶ 🔮 Hint
Ask "Find potential bugs in the transaction validation logic", then edit to fix
★

Challenge 2: Performance Optimization

Task: Transaction list is slow with 1000+ items - optimize rendering.

Use Agent mode with performance analysis request
Review suggested optimizations
Apply React.memo and pagination changes
Expected Result
Memoized components, pagination implementation, faster rendering
▶ 💬 Prompt 
Analyze the transaction list rendering performance and optimize it:
- Identify performance bottlenecks
- Implement React.memo where appropriate
- Add pagination if transactions list is large
- Ensure the virtualized list works efficiently
★

Challenge 3: Notification Center

Task: Build a notification system to alert users of failed transactions.

Ask mode: Research current notification implementation
Edit mode: Add failed transaction notification type
Agent mode: Build notification center with badge
Expected Result
Complete notification system with unread indicator
▶ 🔮 Hint
Ask "How are notifications currently implemented?", edit notification types, then use Agent to "Implement notification center with unread count badge"

🔑 Key Takeaways

  • Ask Mode = exploration and learning
  • Edit Mode = focused single-file changes
  • Agent Mode = complex multi-file features
  • Always review diffs before applying changes
