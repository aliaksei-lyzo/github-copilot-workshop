Unit Testing with GitHub Copilot

Generate comprehensive test suites efficiently with different Copilot modes.

🎯 Learning Objectives

  • Use ASK mode to explore test scenarios and edge cases
  • Generate specific tests with EDIT mode
  • Create comprehensive test suites with AGENT mode
  • Match existing test patterns and style
🔄
Unit Testing Workflow:
  1. ASK Mode - Understand what to test and explore edge cases
  2. EDIT Mode - Generate specific test cases for known scenarios
  3. AGENT Mode - Generate comprehensive test suites covering multiple scenarios
1

Write Tests for Transaction Utility Functions

Task: Create comprehensive unit tests for transaction utility functions.

📄
Source: src/utils/transactionUtils.ts
Test File: src/__tests__/transactionUtils.test.ts (create new)

Functions to test:

  • hasSufficientFunds(sender, transaction) - checks balance
  • getChargeAmount(sender, transaction) - calculates charge
  • formatFullName(user) - formats name
  • hasDateQueryFields(query) - checks date fields
  • getQueryWithoutFilterFields(query) - removes filters
  • getPaginatedItems(page, limit, items) - paginates array
📚
Context: Project uses Vitest, existing tests in src/__tests__/
Think About It
  • Use ASK to understand edge cases?
  • Is EDIT sufficient for individual tests?
  • Would AGENT be better for complete suite?
  • How ensure testing success and failure cases?
Expected Result
Complete test file with 3-4 utility functions tested, edge cases covered
▶ 🔮 Hint
Multiple functions, need comprehensive coverage = consider full suite generation with AGENT

📚 Testing Decision Framework

❓
Use ASK when:
  • Need to understand edge cases
  • Want to explore test coverage gaps
  • Unfamiliar with code being tested
  • Need to understand existing test patterns
  • Want suggestions for test scenarios
✏️
Use EDIT when:
  • Know exactly what test case to write
  • Adding single specific test
  • Modifying existing test
  • Test scenario straightforward
🤖
Use AGENT when:
  • Need complete test suite for module
  • Want comprehensive coverage (happy path + edge cases)
  • Testing multiple related functions
  • Need both unit and integration tests
🔗
Combine Modes:
  • ASK for scenarios → EDIT/AGENT to generate
  • AGENT for initial suite → EDIT to refine
  • ASK for missing coverage → EDIT to add

💡 Pro Testing Tips

📋
Planning:
  • Use ASK to explore what needs testing
  • Ask about edge cases you might miss
  • Understand test framework patterns first
  • Check existing tests for style consistency
⚡
Generation:
  • EDIT for single tests - focused and quick
  • AGENT for suites - comprehensive coverage
  • Specify test framework (Vitest, Jest) in prompts
  • Request descriptive test names for clarity
✅
Validation:
  • Run tests immediately: yarn test:unit
  • Check coverage - ensure critical paths tested
  • Verify assertions - are they meaningful?
  • Test both success and failure paths

🤔 Reflection Questions

  • Did you think about edge cases before writing tests?
  • Which mode generated better quality tests?
  • How did you ensure comprehensive coverage?
  • What test scenarios did you initially miss?
  • How did you match existing code style?

🔑 Key Takeaway

Strategic planning followed by efficient generation using the right mode for the task produces better test coverage faster.
