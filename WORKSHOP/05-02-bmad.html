BMAD Method: AI-Driven Agile Development

Build More, Architect Dreams - specialized AI agents for complete development lifecycle.

🎯 Learning Objectives

  • Install and configure BMAD Method
  • Understand specialized AI agents
  • Navigate the 4-phase development workflow
  • Create PRD, architecture, and implement features
🤖
What is BMAD Method?

BMAD (Build More, Architect Dreams) is an AI-driven agile development framework that uses specialized AI agents and guided workflows. Unlike generic AI coding assistants, BMAD provides:

  • 19 specialized agents (PM, Architect, Developer, UX Designer, etc.)
  • 50+ guided workflows across 4 development phases
  • Scale-adaptive intelligence (bug fixes to enterprise platforms)
  • Complete development lifecycle support
💡
Key Philosophy
  • Structured agile workflows with AI amplification
  • Specialized expertise through domain-specific agents
  • Phase-based: Analysis → Planning → Solutioning → Implementation
  • Fresh chats for each workflow to avoid hallucinations
⚠️
Prerequisites
  • Node.js 18+ installed
  • VS Code with GitHub Copilot extension
  • Git installed

Install BMAD Method

Goal: Install the BMAD Method CLI and set up your project.

Navigate to project root and install:
cd /path/to/github-copilot-workshop
npx bmad-method@alpha install
💡
During installation, you'll be prompted for:
  • Installation directory (default: current directory)
  • Modules to install (select BMad Method - BMM)
  • IDE selection (select GitHub Copilot)
  • VS Code settings configuration (use recommended defaults)
New Files Created
  • .bmad/ - Configuration folder
  • .github/agents/ - BMAD agents
  • .vscode/settings.json - Updated settings

Understand BMAD Agents

Goal: Learn about the specialized AI agents available in BMAD.

Agent Role When to Use
Analyst Initializes workflows, tracks status Starting new projects
PM Creates requirements & specifications PRD, tech specs, epics
Architect Designs system architecture Technical planning
UX-Designer Creates UX specifications UI/UX design
SM Scrum Master - manages sprints Story creation, sprint planning
DEV Implements code, reviews work Actual implementation
Open Copilot Chat (Ctrl+Shift+I or Cmd+Shift+I)
Click on the agent selector (top of chat panel)
Look for BMAD agents (prefixed with "bmd-")
Select "bmd-custom-bmm-analyst" to activate the Analyst

Understand the User Story

Goal: Familiarize yourself with the feature we'll build using BMAD.

📋
User Story: Transaction Insights Dashboard

"As a user of the Real World App, I want to see a transaction insights dashboard that shows spending patterns over time, so that I can understand my financial habits better."

The dashboard should include:

  • Monthly spending breakdown by category
  • Week-over-week spending comparison chart
  • Average transaction amount trends
  • Most frequent transaction contacts
  • Interactive date range filter

The dashboard should:

  • Load quickly with cached data
  • Update in real-time when new transactions occur
  • Be accessible from the main navigation
  • Work on both desktop and mobile views

Initialize BMAD Workflow

Goal: Set up BMAD tracking and determine the right workflow track.

📊
BMAD Tracks:
  • Quick Flow: Bug fixes, small features (< 15 stories typically)
  • BMad Method: Products, platforms, complex features (10-50+ stories)
  • Enterprise Method: Compliance, scale, governance (30+ stories)
Activate the Analyst agent in Copilot Chat
Run workflow initialization:
▶ 💬 Prompt 
*workflow-init

I want to build a transaction insights dashboard for an existing React/Express application. 
This is a new feature that adds spending analytics with charts, filters, and real-time updates.
Expected Output
  • Agent recommends a track (likely BMad Method for this feature)
  • File created: docs/bmm-workflow-status.yaml
  • Clear next steps provided

Create PRD (Phase 2 - Required)

Goal: Create a Product Requirements Document with detailed specifications.

⚠️
Important: Always start a FRESH chat for each workflow!
Start a NEW chat session
Activate the PM agent (select bmd-custom-bmm-pm)
Run the PRD workflow:
▶ 💬 Prompt 
*prd

Create a PRD for the Transaction Insights Dashboard. This is a new feature
for an existing React/Express/TypeScript application that uses lowdb for 
data storage. 

Key requirements:
- Monthly spending breakdown with charts
- Week-over-week comparison
- Average transaction trends
- Frequent contacts display
- Date range filtering
- Real-time updates when new transactions occur
- Mobile-responsive design
- Fast loading with data caching

Reference existing patterns in backend/transaction-routes.ts and 
src/components/ for consistency.
Expected Output
File created: docs/PRD.md containing:
  • Functional Requirements (FRs)
  • Non-Functional Requirements (NFRs)
  • User stories with acceptance criteria
  • Constraints and assumptions
7

Create Architecture (Phase 3 - Required)

Goal: Design the technical architecture for the feature.

Start a FRESH chat
Activate the Architect agent (bmd-custom-bmm-architect)
Run the architecture workflow:
▶ 💬 Prompt 
*create-architecture

Design the architecture for the Transaction Insights Dashboard.

Tech Stack Context:
- Backend: Express.js with TypeScript (see backend/app.ts)
- Database: lowdb JSON database (see backend/database.ts)
- Frontend: React with Material-UI
- Existing patterns: backend/transaction-routes.ts, src/components/

Architecture should address:
- New API endpoints for analytics data
- Data aggregation and caching strategy
- Chart library selection (consider recharts or chart.js)
- Real-time update mechanism
- State management approach
- Component structure
Expected Output
Architecture document with:
  • System design decisions
  • API endpoint specifications
  • Data flow diagrams
  • Technology choices with rationale

Create Epics and Stories

Goal: Break down the PRD into implementable epics and stories.

Start a FRESH chat
Activate the PM agent
Run the epics workflow:
▶ 💬 Prompt 
*create-epics-and-stories
Expected Epic Breakdown
  • Epic 1: Analytics API Layer
  • Epic 2: Data Aggregation Service
  • Epic 3: Dashboard UI Components
  • Epic 4: Real-time Updates
  • Epic 5: Testing and Polish

Each epic contains multiple user stories with acceptance criteria.

9

Sprint Planning and Implementation (Phase 4)

Goal: Set up sprint tracking and implement stories.

Step 1: Sprint Planning (SM Agent)

▶ 💬 Prompt 
*sprint-planning

Step 2: Create Story (SM Agent - Fresh Chat)

▶ 💬 Prompt 
*create-story

Step 3: Implement Story (DEV Agent - Fresh Chat)

▶ 💬 Prompt 
*dev-story

Step 4: Code Review (DEV Agent - Fresh Chat)

▶ 💬 Prompt 
*code-review
🔄
For Each Story, Repeat:
  1. NEW chat → SM agent → "*create-story"
  2. NEW chat → DEV agent → "*dev-story"
  3. NEW chat → DEV agent → "*code-review" (optional)
⚡
Quick Flow Alternative

For smaller tasks (bug fixes, simple features), use Quick Flow:

  1. Start with Analyst agent
  2. Run workflow-init and select Quick Flow track
  3. Create tech-spec instead of full PRD: *tech-spec
  4. Implement directly with DEV agent

Quick Flow is 3 steps: tech-spec → dev → optional review

📊
Complete BMAD Method Workflow
Phase 1 - Analysis (Optional):
  • workflow-init → Set up tracking
  • brainstorm-project → Explore ideas
  • product-brief → Clarify vision
Phase 2 - Planning (Required):
  • prd → Create requirements
  • ux → Design user experience (if UI involved)
Phase 3 - Solutioning (Required):
  • create-architecture → Design system
  • create-epics-and-stories → Break down work
  • implementation-readiness → Validate plans
Phase 4 - Implementation (Required):
  • sprint-planning → Set up tracking
  • create-story → Draft next story
  • dev-story → Implement code
  • code-review → Quality check
  • retrospective → Epic completion review

🔑 Key Learnings

  • Fresh Chats for Each Workflow: Prevents context pollution and hallucinations
  • Specialized Agents = Better Results: Each agent has deep domain expertise
  • Track Matters: Quick Flow for small tasks, BMad Method for features
  • Tracking is Automatic: YAML files track status as you work
  • Flexible Command Input: Use shorthand (*prd), menu numbers, or natural language
