GitHub Copilot Prompt Files

Create reusable, shareable prompt templates for consistent code generation.

🎯 Learning Objectives

  • Understand what prompt files are and when to use them
  • Create reusable prompt files for common tasks
  • Write effective custom prompts referencing project patterns
  • Build a prompt library for your team
📄
What Are Prompt Files?

Prompt files (.github/copilot-prompts/*.md) are reusable, shareable instructions that:

  • Stored in repository and version-controlled
  • Invoked in Copilot Chat with # command
  • Define reusable patterns for common tasks
  • Maintain consistency across team
  • Save time by eliminating repetitive context-setting
📁
File Structure: 
.github/
  copilot-prompts/
    form-component.md
    api-route.md
    unit-test.md
    bug-fix.md
📝
File Format: 
---
description: Brief description shown in Copilot Chat
---

# Prompt Title

[Detailed instructions for Copilot]
[Can include code examples]
[Can reference project patterns]
[Can guide what user should provide]
1

Create Form Component Prompt File

Task: Create reusable prompt file that generates form components matching project patterns.

📄
File: .github/copilot-prompts/form-component.md (create new)
📚
Context: Forms use Material-UI styled components (PREFIX pattern), Formik, Yup validation, TypeScript interfaces

Prompt File Must Include:

  1. Frontmatter with description
  2. Reference to existing patterns (CommentForm.tsx, BankAccountForm.tsx)
  3. Material-UI styled components with PREFIX pattern
  4. Formik + Yup validation requirements
  5. TypeScript interfaces for props and payload
  6. data-test attributes requirement
  7. Field-level error display
  8. Guidance on what user should provide
Think About It
  • How structure prompt so users know what to specify?
  • Should you include code snippets as examples?
  • How ensure consistency without being too rigid?
  • What validation patterns should be highlighted?
Expected Result
Prompt file that appears in Chat, generates compilable forms following project patterns
▶ 🔮 Hint
Study existing forms first, reference them in prompt, provide clear structure for user input

Create Custom Form with Prompt Engineering

Task: Write a custom prompt in Chat to generate BankTransferForm component matching existing patterns.

Requirements:

Field Type Validation
bankAccountId dropdown required, UUID
amount number min 0.01, max 5000, required
description text max 100 chars, required

Additional Specs:

  • Props Interface: bankAccounts: BankAccount[], onSubmit: (values: BankTransferPayload) => void
  • Pattern: CommentForm.tsx, BankAccountForm.tsx
  • Styling: PREFIX pattern with Material-UI
  • Location: src/components/BankTransferForm.tsx
Think About It
  • How reference existing patterns in prompt?
  • Should you include file paths to similar components?
  • How specific should validation rules be?
  • What info does Copilot need to match style?
Expected Result
Complete, compilable component matching existing form patterns
▶ 🔮 Hint
Reference specific files, be explicit about validation, mention TypeScript interfaces
3

Create API Route Generation Prompt Template

Task: Create reusable prompt template for generating API routes, then use it for banktransfer-routes.ts.

📚
Context: Existing patterns in transaction-routes.ts, bankaccount-routes.ts use Express, TypeScript, express-validator, centralized database utilities

New Endpoints:

Endpoint Description Details
GET /banktransfers List transfers with pagination Query: page, limit. Auth required
GET /banktransfers/:id Get specific transfer Auth + ownership check. 404/403 errors
POST /banktransfers Create transfer Validate funds, deduct balance. 201/400/402

Template Should Include:

  • Proper imports (express, validators, database utils)
  • Router initialization
  • Route handlers with TypeScript types
  • Express-validator middleware
  • Consistent error handling
  • Proper HTTP status codes
  • Database operations via utilities
  • Authentication checks
  • JSDoc comments
Expected Result
Complete route file following existing patterns with proper validation and error handling
▶ 🔮 Hint
Analyze existing routes, identify common structure, create template with placeholders, use AGENT mode

📚 Custom Prompt Best Practices

✅
DO:
  • Be specific about patterns and conventions
  • Reference existing files for context
  • Include examples of desired output
  • Specify frameworks/libraries used
  • Define error handling expectations
  • Use TypeScript types when applicable
  • Test prompts and iterate
❌
DON'T:
  • Be too vague ("make it good")
  • Contradict existing code patterns
  • Omit important context about project
  • Forget edge cases and error scenarios
  • Ignore existing validation patterns
  • Mix different styles in one prompt

💡 Prompt Engineering Tips

1
Reference Existing Code:
  • "Follow pattern in CommentForm.tsx"
  • "Use same validation approach as transaction-routes.ts"
  • "Match styling of existing components"
2
Specify Constraints:
  • "Must use existing database.ts utilities, not raw SQL"
  • "Validators must be in validators.ts file"
  • "Error messages must match existing format"
3
Include Success Criteria:
  • "Component should compile without TypeScript errors"
  • "All routes should have proper authentication checks"
  • "Form should match styling of BankAccountForm"
4
Iterate and Refine:
  • Generate → Review → Adjust prompt → Regenerate
  • Save working prompts for reuse
  • Build prompt library for common tasks

🔑 Key Takeaways

  • Reusable prompts save time on repetitive tasks
  • Well-crafted prompts generate better code faster
  • Reference existing code instead of describing patterns
  • Be specific about validation, errors, edge cases
  • Iterate and refine prompts based on results
  • Build library of proven prompts for common tasks
  • Share with team to maintain consistency
