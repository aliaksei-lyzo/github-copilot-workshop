Custom Copilot Instructions

Configure project-specific and global instructions to improve Copilot's output quality and consistency.

🎯 Learning Objectives

  • Understand three types of Copilot instructions and their priority
  • Create and test custom instructions
  • Observe how instructions change AI output
  • Learn what makes instructions effective vs ineffective
📚
Instruction Types & Priority (highest to lowest):
  1. Chat Instructions (inline in prompt) - overrides everything
  2. Repository Instructions (.github/copilot-instructions.md) - overrides global
  3. Global Instructions (VS Code Settings) - overrides default
  4. Default Copilot Behavior
1

Baseline - No Instructions

Task: Establish baseline by testing Copilot without any custom instructions.

Ensure no .github/copilot-instructions.md exists in this project
Clear any Global instructions (VS Code Settings → GitHub Copilot › Chat: Instructions)
Test these 3 prompts in Copilot Chat and save the output
▶ 💬 Test Prompts

Prompt 1:

Create a function to calculate transaction fees

Prompt 2:

Create a React component for displaying user profile

Prompt 3:

Create an API endpoint to fetch transactions
Expected Result
Baseline output showing default Copilot behavior (style, structure, what's included/missing)
▶ 🔮 Hint
Save results in a file called baseline-results.txt for comparison later
2

Create Repository Instructions

Task: Create instructions file with mix of good and problematic rules to learn what works.

Create .github/copilot-instructions.md in this project
Add rules (some intentionally vague to demonstrate what doesn't work)
▶ 📄 Instructions Content (with intentional issues) 
### Code Style
- Always use TypeScript with strict mode enabled
- Write good code and follow best practices

### Documentation
- Add JSDoc comments to all exported functions
- Document everything properly

### Testing
- Use Vitest for all unit tests
- Test file should be alongside source file with .test.ts extension
⚠️
Note: Rules 2 and 4 are intentionally vague to show ineffective instructions.

Part 2: Test and Observe

Save .github/copilot-instructions.md
Reload VS Code window (Cmd+Shift+P → "Reload Window")
Run the SAME 3 prompts from Exercise 1
Compare with baseline results
Questions to answer
  • Which rules did Copilot follow? (Hint: specific ones like TypeScript, Vitest)
  • Which rules were ignored? (Hint: vague ones like "good code")
  • What's the difference between specific vs vague instructions?
3

Fix the Vague Instructions

Task: Rewrite the 2 vague rules to be specific and actionable.

Identify which 2 rules from Exercise 2 didn't work (the vague ones)
Rewrite them to be specific
Save updated .github/copilot-instructions.md
Reload VS Code
Test with new prompts
▶ ✅ Improved Rules

Change from: "Write good code and follow best practices"

Change to:

Use descriptive variable names, max 20 lines per function, avoid nested ternaries

Change from: "Document everything properly"

Change to:

Include @param and @returns tags in JSDoc, add example usage for functions with 3+ parameters
▶ 💬 New Test Prompts

Prompt 4:

Create a function to validate email addresses

Prompt 5:

Create a utility function to format currency
Expected Result
Copilot now follows the rewritten specific rules
4

Test Instruction Priority

Task: Understand how different instruction levels interact and override each other.

Part 1: Add Global Instructions

Open VS Code Settings (Cmd+,)
Search for "GitHub Copilot Instructions"
Find "GitHub Copilot › Chat: Instructions"
Add: Always include console.log statements for debugging

Part 2: Test Non-Conflicting Rules

📋

Your repository says: "Use TypeScript with strict mode"

Your global says: "Always include console.log statements"

▶ 💬 Test Prompt 
Create a utility function to format dates
Questions
  • Does output use TypeScript? (Yes - repository rule)
  • Does output include console.log? (Yes - global rule)
  • Both rules are followed because they don't conflict

Part 3: Create Actual Conflict

Add to Global instructions: Never use TypeScript, always use JavaScript
Repository still says: "Always use TypeScript with strict mode"
Test prompt: Create a function to parse JSON safely
Expected Result
Repository wins! TypeScript is used because Repository > Global in priority
5

Chat Instructions (Highest Priority)

Task: Override repository rules temporarily using chat instructions.

Part 1: Override Repository Rules

Your repository says: "Use TypeScript with strict mode"

▶ 💬 Override Prompt 
For this task only: ignore TypeScript rules, use plain JavaScript.

Create a quick prototype function to shuffle an array
Expected Result
JavaScript output despite repository requiring TypeScript

Part 2: Add Domain-Specific Context

▶ 💬 Context Prompt 
Context: Financial application handling money
Rules:
- Use Decimal.js for all currency calculations (never native numbers)
- Round all amounts to 2 decimal places
- Validate amounts are positive before processing

Create a function to calculate transaction fees with 2.5% rate
Expected Result
Function using Decimal.js, proper rounding, validation
▶ 🔮 Hint
"For this task only" makes Copilot temporarily ignore other instructions. Inline context adds specialized knowledge not in repository instructions.
6

File-Specific Custom Instructions

Task: Create instructions that apply only to specific file types.

Part 1: Create Frontend Instructions

Open Command Palette (Cmd+Shift+P)
Run: "Chat: New Instructions File"
Select default folder (.github/instructions)
Name file: "frontend"
In applyTo field, specify frontend file patterns
▶ 📄 ApplyTo Patterns 
src/components/**/*.tsx
src/containers/**/*.tsx
src/hooks/**/*.ts
▶ 📄 Frontend Rules 
- Use Material-UI components exclusively
- Every interactive element must have data-test attribute
- Use React functional components with hooks only
- Implement loading states and error boundaries

Part 2: Create Test Instructions

▶ 📄 Test ApplyTo Patterns 
**/*.test.ts
**/*.test.tsx
src/__tests__/**/*.ts
▶ 📄 Test Rules 
- Use Vitest framework with describe/it/expect syntax
- Test happy path, edge cases, and error scenarios
- Use Arrange-Act-Assert pattern
- Mock external dependencies and API calls
- Include descriptive test names
Expected Result
Different instructions applied based on file type/location. Frontend files get MUI + data-test. Test files get Vitest + AAA pattern.

🔑 Key Takeaways

  • Effective Instructions Are: Specific ("Use Vitest"), Actionable (clear what to do), Testable (you can verify if followed), Consistent (no contradictions)
  • Ineffective Instructions Are: Vague ("Write good code"), Ambiguous ("Document properly"), Contradictory (conflicting rules)
  • Priority: Chat > Repository > Global > Default
  • When to Use Each: Chat for one-off tasks, Repository for team standards, Global for personal preferences

✅ Completion Checklist

  • Established baseline without instructions
  • Created repository instructions with mix of rules
  • Identified which rules work (specific) vs don't work (vague)
  • Rewrote vague rules to be specific
  • Tested instruction priority (Repository > Global)
  • Used chat instructions to override temporarily
  • Created file-specific instructions
  • Can explain why specific > vague
