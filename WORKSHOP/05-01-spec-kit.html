Spec Kit: Specification-Driven Development

Define WHAT you want before HOW to build it with structured specifications.

🎯 Learning Objectives

  • Install and configure Spec Kit CLI
  • Create project constitution and specifications
  • Generate implementation plans and task breakdowns
  • Execute systematic implementation
📐
What is Spec Kit?

Spec Kit is an open-source toolkit from GitHub that enables Specification-Driven Development (SDD). Instead of "vibe coding" from scratch, you:

  • Define WHAT you want before HOW to build it
  • Generate structured specifications from natural language
  • Create implementation plans with your tech stack
  • Break down into actionable tasks
  • Execute implementation systematically
💡
Key Philosophy
  • Specifications become executable (not just documentation)
  • Multi-step refinement instead of one-shot code generation
  • Intent-driven development (what & why before how)
⚠️
Prerequisites
  • Python 3.11+ installed
  • uv package manager installed (docs.astral.sh/uv)
  • Git installed
  • VS Code with GitHub Copilot extension
1

Install Spec Kit CLI

Goal: Install the Specify CLI tool to enable spec-driven development.

Installation Options

▶ Option A: Persistent Installation (Recommended) 
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
▶ Option B: One-time Usage 
uvx --from git+https://github.com/github/spec-kit.git specify check

Verify Installation

specify check
Expected Output
  • List of detected tools (git, VS Code, etc.)
  • "Specify CLI is ready to use!" message
🔧
Troubleshooting:
  • If "command not found": Ensure uv is in PATH
  • If Python errors: Verify Python 3.11+

Initialize Spec Kit in Project

Goal: Bootstrap Spec Kit in the workshop project with GitHub Copilot support.

Navigate to project root:
cd /path/to/github-copilot-workshop
Initialize Spec Kit for GitHub Copilot:
specify init --here --force --ai copilot
New Files Created
  • .github/prompts/ - Speckit commands
  • scripts/bash/ - Helper scripts
  • templates/ - Specification templates
  • memory/ - Constitution folder
📁
Available Slash Commands:
  • /speckit.specify - Create feature specification
  • /speckit.plan - Generate implementation plan
  • /speckit.tasks - Create task breakdown
  • /speckit.implement - Execute implementation

Understand the User Story

Goal: Familiarize yourself with the feature we'll build using SDD.

📋
User Story: Weekly Transaction Summary

"As a user of the Real World App, I want to receive weekly summary emails of my transaction activity so that I can stay informed about my spending without logging into the app daily."

The weekly summary should include:

  • Total transactions count and amount for the week
  • Top 3 transaction categories by spending
  • Comparison with previous week (up/down percentage)
  • Quick link to view full transaction history

Users should be able to:

  • Enable/disable weekly summaries in profile settings
  • Choose the day of the week to receive summaries (default: Monday)
  • Select summary format (detailed or brief)
❓
Questions to Answer:
  • What new backend endpoints are needed?
  • What new database fields are required?
  • What new UI components are necessary?
  • What's unclear and needs clarification?

Establish Project Constitution

Goal: Create project principles that guide all AI-generated code.

📜
The constitution defines coding standards, architectural decisions, and quality requirements that Copilot must follow.
Open GitHub Copilot Chat (Ctrl+Shift+I or Cmd+Shift+I)
Use the constitution command:
▶ 💬 Prompt 
/speckit.constitution Create principles focused on:
- TypeScript strict mode with explicit types
- Express.js patterns matching existing routes (see backend/transaction-routes.ts)
- React functional components with hooks
- Material-UI styling following existing patterns
- JSON database using lowdb patterns
- Comprehensive error handling with proper HTTP codes
- Test-first development approach
- JSDoc comments for all public functions
Expected Output
  • File created: memory/constitution.md
  • Contains coding standards, testing requirements, architectural decisions
  • Specific to this project's stack
5

Create Feature Specification (/speckit.specify)

Goal: Transform the user story into a structured feature specification.

▶ 💬 Prompt 
/speckit.specify Build a weekly transaction summary email feature for users. 
Users can enable/disable weekly summaries in profile settings, choose which 
day to receive them (default Monday), and select between detailed or brief 
format. Summary includes: total transactions count and amount, top 3 spending 
categories, comparison with previous week, and link to full history. 
This integrates with the existing Express backend, React frontend, and 
lowdb database.
Expected Output
  • New branch created (e.g., 001-weekly-summary)
  • File: specs/001-weekly-summary/spec.md containing:
    • User Scenarios & Testing section
    • Requirements section
    • Success Criteria section
    • Possibly [NEEDS CLARIFICATION] markers
6

Clarify Specification Requirements (/speckit.clarify)

Goal: Resolve any unclear aspects in the specification before planning.

▶ 💬 Prompt 
/speckit.clarify Address the following:
1. Email delivery: Use a mock email service (console.log) for development
2. Scheduling: Use node-cron for weekly job scheduling
3. Time zone: Store user preference, default to UTC
4. Email template: Simple HTML with inline CSS
5. Retry logic: 3 attempts with exponential backoff for failed sends
Expected Output
Updated spec.md with clarifications resolved

Create Implementation Plan (/speckit.plan)

Goal: Generate a technical implementation plan with architecture decisions.

▶ 💬 Prompt 
/speckit.plan The implementation uses:
- Express.js backend with TypeScript (match existing patterns in backend/)
- lowdb JSON database (see backend/database.ts for patterns)
- React frontend with Material-UI (see src/components/)
- node-cron for scheduling
- Mock email service (console.log for now)
- Integration with existing user-routes.ts for preferences
- New email-service.ts for summary generation
- New scheduled-jobs.ts for cron scheduling
Files Created in specs/001-weekly-summary/
  • plan.md - Implementation plan with phases
  • research.md - Technology research and decisions
  • data-model.md - Database schema changes
  • quickstart.md - Key validation scenarios
  • contracts/ - API endpoint specifications

Generate Task Breakdown (/speckit.tasks)

Goal: Break down the implementation plan into actionable tasks.

▶ 💬 Prompt 
/speckit.tasks
Expected Output
File: specs/001-weekly-summary/tasks.md containing:
  • Phase-organized task list
  • Task IDs and descriptions
  • File paths for each task
  • Dependencies between tasks
  • [P] markers for parallelizable tasks
📋
Sample Expected Tasks:
  • Setup: Configure node-cron dependency
  • Tests: Write tests for summary generation
  • Core: Implement email-service.ts
  • Core: Add user preference fields
  • Integration: Create preferences API endpoint
  • Integration: Build PreferencesPanel component
  • Polish: Add loading states and error handling

10

Begin Implementation (/speckit.implement)

Goal: Execute the implementation plan systematically.

⚠️
Important: This task modifies your codebase. Consider:
  • Working on a feature branch (already created by /speckit.specify)
  • Having tests ready to verify changes
  • Reviewing changes incrementally
▶ 💬 Prompt 
/speckit.implement
🔄
What Happens:
  1. Validates prerequisites (constitution, spec, plan, tasks)
  2. Parses task breakdown from tasks.md
  3. Executes tasks in order, respecting dependencies
  4. Follows TDD approach from task plan
  5. Provides progress updates
📊
Complete SDD Workflow
  1. /speckit.constitution → Project principles
  2. /speckit.specify → Feature specification from user story
  3. /speckit.clarify → Resolve ambiguities
  4. /speckit.plan → Technical implementation plan
  5. /speckit.tasks → Actionable task breakdown
  6. /speckit.checklist → Pre-implementation validation
  7. /speckit.analyze → AI audit of artifacts
  8. /speckit.implement → Execute implementation

Time Comparison:
Traditional: ~12 hours documentation + implementation
SDD: ~30 minutes specification + systematic implementation

🔑 Key Learnings

  • Specification First: Define WHAT before HOW. Clear specs lead to better code.
  • Structured Process: Each step builds on previous, reducing ambiguity and rework.
  • AI-Assisted, Human-Guided: AI generates artifacts, human reviews and refines.
  • Consistency Through Constitution: Project principles prevent drift.
  • Iterative Refinement: Review → Analyze → Adjust → Continue.
🔧
Troubleshooting
  • "Slash commands not recognized": Verify .github/prompts/ folder exists. Re-run: specify init --here --force --ai copilot
  • "Branch not detected": Ensure you're on feature branch or set: export SPECIFY_FEATURE="001-weekly-summary"
  • "Script permission denied": Run: chmod +x scripts/bash/*.sh
