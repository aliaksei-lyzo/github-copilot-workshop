SPEC KIT: SPECIFICATION-DRIVEN DEVELOPMENT
===========================================

WHAT IS SPEC KIT?

Spec Kit is an open-source toolkit from GitHub that enables Specification-Driven Development (SDD).
Instead of "vibe coding" from scratch, you:
- Define WHAT you want before HOW to build it
- Generate structured specifications from natural language
- Create implementation plans with your tech stack
- Break down into actionable tasks
- Execute implementation systematically

Key Philosophy:
- Specifications become executable (not just documentation)
- Multi-step refinement instead of one-shot code generation
- Intent-driven development (what & why before how)
- Heavy reliance on AI model capabilities

---

PREREQUISITES

Before starting:
1. Python 3.11+ installed
2. uv package manager installed (https://docs.astral.sh/uv/)
3. Git installed
4. VS Code with GitHub Copilot extension
5. This workshop project cloned

---

TASK 1: INSTALL SPEC KIT CLI

Goal: Install the Specify CLI tool to enable spec-driven development.

Steps:

1. Open terminal in VS Code (Ctrl+` or Cmd+`)

2. Install Specify CLI (choose one method):

   Option A - Persistent Installation (Recommended):
   ```bash
   uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
   ```

   Option B - One-time Usage:
   ```bash
   uvx --from git+https://github.com/github/spec-kit.git specify check
   ```

3. Verify installation:
   ```bash
   specify check
   ```

Expected Output:
- List of detected tools (git, VS Code, etc.)
- "Specify CLI is ready to use!" message

Troubleshooting:
- If "command not found": Ensure uv is in PATH
- If Python errors: Verify Python 3.11+

TASK 2: INITIALIZE SPEC KIT IN PROJECT

Goal: Bootstrap Spec Kit in the workshop project with GitHub Copilot support.

Steps:

1. Navigate to project root:
   ```bash
   cd /path/to/github-copilot-workshop
   ```

2. Initialize Spec Kit for GitHub Copilot:
   ```bash
   specify init --here --ai copilot
   ```

   If directory has files (it does), add --force:
   ```bash
   specify init --here --force --ai copilot
   ```

3. Verify initialization - check for new files:
   - .github/prompts/ folder with speckit commands
   - scripts/bash/ folder with helper scripts
   - templates/ folder with specification templates
   - memory/ folder for constitution

Expected Output:
- New folders: .github/prompts/, scripts/, templates/, memory/

TASK 3: UNDERSTAND THE USER STORY

Goal: Familiarize yourself with the feature we'll build using SDD.

User Story:

"As a user of the Real World App, I want to receive weekly summary emails 
of my transaction activity so that I can stay informed about my spending 
without logging into the app daily.

The weekly summary should include:
- Total transactions count and amount for the week
- Top 3 transaction categories by spending
- Comparison with previous week (up/down percentage)
- Quick link to view full transaction history

Users should be able to:
- Enable/disable weekly summaries in their profile settings
- Choose the day of the week to receive summaries (default: Monday)
- Select summary format (detailed or brief)"

Technical Context:
- Backend: Express.js with TypeScript
- Database: JSON-based (lowdb)
- Frontend: React with Material-UI
- Existing patterns: See backend/transaction-routes.ts, src/components/

Action:
1. Read the user story carefully
2. Identify key requirements
3. Note any unclear aspects

Questions to Answer:
- What new backend endpoints are needed?
- What new database fields are required?
- What new UI components are necessary?
- What's unclear and needs clarification?

TASK 4: ESTABLISH PROJECT CONSTITUTION

Goal: Create project principles that guide all AI-generated code.

Context: The constitution defines coding standards, architectural decisions, and quality requirements that Copilot must follow.

Action:
1. Open GitHub Copilot Chat (Ctrl+Shift+I or Cmd+Shift+I)
2. Use the constitution command:

Prompt:
```
/speckit.constitution Create principles focused on:
- TypeScript strict mode with explicit types
- Express.js patterns matching existing routes (see backend/transaction-routes.ts)
- React functional components with hooks
- Material-UI styling following existing patterns
- JSON database using lowdb patterns
- Comprehensive error handling with proper HTTP codes
- Test-first development approach
- JSDoc comments for all public functions
```

Expected Output:
- File created: memory/constitution.md
- Contains coding standards, testing requirements, architectural decisions
- Specific to this project's stack

Questions:
- Why is the constitution important for AI-generated code?
- How does this prevent "vibe coding"?
- Can you modify the constitution later?

WORKFLOW SUMMARY

Complete SDD Workflow:

1. /speckit.constitution → Project principles
2. /speckit.specify → Feature specification from user story
3. /speckit.clarify → Resolve ambiguities
4. /speckit.plan → Technical implementation plan
5. /speckit.tasks → Actionable task breakdown
6. /speckit.checklist → Pre-implementation validation
7. /speckit.analyze → AI audit of artifacts
8. /speckit.implement → Execute implementation

Time Comparison:
Traditional Approach: ~12 hours documentation + implementation
SDD Approach: ~30 minutes specification + systematic implementation

---

KEY LEARNINGS

1. Specification First
   - Define WHAT before HOW
   - Clear specs lead to better code

2. Structured Process
   - Each step builds on previous
   - Reduces ambiguity and rework

3. AI-Assisted, Human-Guided
   - AI generates artifacts
   - Human reviews and refines
   - Best of both worlds

4. Consistency Through Constitution
   - Project principles prevent drift
   - AI follows established patterns

5. Iterative Refinement
   - Review → Analyze → Adjust → Continue
   - Not one-shot generation

TROUBLESHOOTING

"Slash commands not recognized"
→ Verify .github/prompts/ folder exists
→ Re-run: specify init --here --force --ai copilot

"Branch not detected"
→ Ensure you're on feature branch (001-weekly-summary)
→ Or set: export SPECIFY_FEATURE="001-weekly-summary"

"Templates not found"
→ Check templates/ folder exists
→ Re-run initialization

"Script permission denied"
→ Run: chmod +x scripts/bash/*.sh
