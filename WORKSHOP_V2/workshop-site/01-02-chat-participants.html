Chat Participants

Learn to use @workspace, @terminal, and @github to get specialized help in different contexts.

🎯 Learning Objectives

  • Use @workspace to understand project architecture and code patterns
  • Use @terminal to get help with command-line operations
  • Use @github to query repository history, issues, and PRs
  • Combine multiple participants for complex queries
1

@workspace Participant

Task: Explore authentication architecture using @workspace.

Open Copilot Chat
Ask about the authentication implementation across frontend and backend
▶ 💬 Suggested Prompt 
@workspace How is authentication implemented across the frontend and backend? Which files are involved?
Expected Result
Overview of auth architecture, list of files (auth.ts, user-routes.ts, auth providers), explanation of frontend/backend connection, references to Auth0/Okta/Cognito/Google
▶ 🔮 Hint
@workspace understands entire codebase context
Follow-up questions to try
  • "@workspace Where are the transaction models defined and how are they used?"
  • "@workspace What testing strategy is used in this project?"
  • "@workspace How are React state machines (XState) organized in this codebase?"
  • "@workspace What is the database structure and how is it seeded?"
📚
When to use @workspace:
  • Understanding how different parts connect
  • Finding where specific functionality is implemented
  • Learning about design patterns used
  • Getting overview of project architecture
2

@terminal Participant

Task: Learn testing and database commands using @terminal.

Open Copilot Chat
Ask about running specific tests with coverage
▶ 💬 Suggested Prompt 
@terminal How do I run only the Cypress API tests and generate a coverage report?
Expected Result
Correct command(s) for API tests with coverage, explanation of flags/options, possibly suggests yarn test:api
▶ 🔮 Hint
@terminal gives command-line help specific to your project
Follow-up questions to try
  • "@terminal How can I check which port the backend is running on?"
  • "@terminal Show me how to reset the database and reseed it"
  • "@terminal How do I find all TypeScript files that import the Transaction model?"
  • "@terminal What command shows me the size of node_modules?"
  • "@terminal How do I run the linter and fix issues automatically?"
✅
Practice: Execute suggested commands in terminal to verify they work
📚
When to use @terminal:
  • Need help with shell commands
  • Don't remember script names from package.json
  • Want to combine multiple terminal operations
  • Need help with git commands
  • Looking for file search or text manipulation commands
3

@github Participant

Task: Research repository history using @github.

Make sure GitHub Copilot is connected to repository
Open Copilot Chat
Ask about issues or PRs related to specific features
▶ 💬 Suggested Prompt 
@github What issues or pull requests relate to authentication features?
Expected Result
List of related issues/PRs (if any exist), summary of auth-related changes, links to discussions
▶ 🔮 Hint
@github requires internet connection and repository access
Follow-up questions to try
  • "@github What are the recent changes to the transaction model?"
  • "@github Are there any open issues related to testing?"
  • "@github Show me the commit history for the database.ts file"
  • "@github What dependencies were recently updated?"
  • "@github Are there any security-related discussions or issues?"
📚
When to use @github:
  • Understanding why code was written a certain way
  • Finding related issues or discussions
  • Checking commit history for specific files
  • Looking for existing bug reports or feature requests
  • Understanding project evolution over time
4

Combining Chat Participants

Task: Complete development workflow using multiple participants.

Scenario: Understand full workflow for making changes, testing, and deploying.

Step 1 - Understand Structure:

▶ 💬 Suggested Prompt 
@workspace What is the complete workflow for testing and deploying changes in this project? What files and processes are involved?

Step 2 - Get Commands:

▶ 💬 Suggested Prompt 
@terminal Give me the exact commands to: 1) run type checking, 2) run all tests, 3) build for production. Chain them together so they only run if the previous succeeds.

Step 3 - Check Automation:

▶ 💬 Suggested Prompt 
@github Is there a CI/CD pipeline configured for this repository? Show me the workflow files and what they do.
Expected Result
Complete understanding of dev workflow, executable command chain, knowledge of automation, clear best practices
▶ 🔮 Hint
Chain participants from broad (@workspace) to specific (@terminal/@github)

📋 Choosing the Right Participant

Participant Best For Example Query
@workspace Code structure, architecture "How does authentication work?"
@terminal Commands, scripts, file ops "How do I run tests with coverage?"
@github History, issues, PRs, collab "What recent changes affected API?"
(none) General programming questions "How does async/await work in TypeScript?"
💡
Tips for Effective Queries:
  • Be Specific: Instead of "How do I test?", ask "How do I run Cypress E2E tests for transaction feature?"
  • Provide Context: Mention specific files or features
  • Chain Questions: Start broad with @workspace, then narrow with @terminal or @github
  • Verify Answers: Always test suggested commands before using in production
  • Use Multiple Participants: Complex questions benefit from multiple perspectives
🎯
Real-world Scenarios to Practice:
  • New Team Member Onboarding: @workspace → @terminal → @github
  • Bug Investigation: @workspace to find code → @github to check if reported → @terminal to reproduce
  • Feature Implementation: @workspace to find patterns → @terminal to set up tests → @github for discussions
  • Performance Optimization: @workspace to identify bottlenecks → @terminal to profile → @github for history

✅ Completion Checklist

  • Used @workspace to understand project architecture
  • Used @terminal to get command-line help
  • Used @github to query repository history
  • Combined multiple participants in single workflow
  • Executed suggested terminal commands successfully
  • Understand when to use each participant
  • Can create multi-step queries independently
