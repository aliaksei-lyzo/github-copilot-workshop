GitHub Copilot Code Review

AI-powered code review locally in VS Code and on GitHub Pull Requests.

🎯 Learning Objectives

  • Set up project-specific code review guidelines
  • Use VS Code "Review and Comment" feature
  • Review all local changes with Copilot Chat
  • Configure automatic PR review on GitHub
  • Interact with Copilot's review comments
👁️
Code Review Capabilities

GitHub Copilot offers powerful code review at two levels:

  • Local Code Review: Review changes in VS Code before committing
  • GitHub PR Review: Automated code review on Pull Requests

⚠️
Intentional Issues:
  • Debug console.log statements
  • TODO/FIXME comments
  • Using var instead of const/let

Exercise 1: Local Code Review

1.1

Create Code Review Custom Instructions

Goal: Set up project-specific code review guidelines for Copilot.

Create or update .github/copilot-instructions.md:
▶ 📄 Review Guidelines Content 
# Code Review Guidelines

When reviewing code in this project, check for:

## Security
- No hardcoded credentials, API keys, or secrets
- Proper input validation and sanitization
- No SQL injection or XSS vulnerabilities

## Code Quality
- Use `const` or `let` instead of `var`
- Use strict equality (=== and !==)
- Proper TypeScript types (no `any` unless justified)
- Remove debug console.log statements before committing
- Remove TODO/FIXME comments or create issues for them
- Delete unused/dead code

## Project Patterns
- Follow existing patterns in `backend/transaction-routes.ts`
- Use express-validator for input validation
- Implement proper error handling with try-catch
- Add JSDoc comments for public functions
1.2

Use VS Code "Review and Comment" Feature

Goal: Use Copilot's built-in code review feature to analyze the problematic code.

Open backend/transfer-utils.ts in the editor
Select the entire file content (Cmd+A / Ctrl+A)
Open Command Palette (Cmd+Shift+P / Ctrl+Shift+P)
Type and select: "GitHub Copilot: Review and Comment"
Wait for Copilot to analyze the code
Expected Findings
  • Debug console.log statements
  • Use of var keyword
  • any type annotations
  • Loose equality operators
  • Potential security issue (hardcoded password)
  • Dead code detection
1.3

Review All Local Changes with Chat

Goal: Use Copilot Chat with #get_changed_files to review all uncommitted changes.

Open Copilot Chat panel
Select a capable model (Claude Sonnet 4 or GPT-4o)
Use the following prompt:
▶ 💬 Prompt 
#get_changed_files Review all my current changes. Look for:
- Security vulnerabilities
- Code quality issues  
- TypeScript best practices violations
- Debug code that should be removed
- Patterns that don't match the rest of the codebase

Provide specific line numbers and suggested fixes.
Expected Output
  • Summary of all changed files
  • Detailed issues found in each file
  • Specific suggestions with code examples
  • Priority ranking of issues
1.4

Fix Issues Based on Review

Goal: Apply fixes suggested by Copilot's review.

▶ 💬 Comprehensive Fix Prompt (Agent Mode) 
Fix all code quality issues in backend/transfer-utils.ts:
1. Remove debug console.log statements
2. Replace var with const/let
3. Add proper TypeScript types (no any)
4. Use strict equality
5. Remove the hardcoded password comment

Keep the existing logic intact.

Exercise 2: GitHub PR Code Review

2.1

Configure Copilot as PR Reviewer

Goal: Set up GitHub repository to automatically request Copilot reviews on PRs.

📋
Prerequisites:
  • Repository admin access
  • GitHub Copilot for Business or Enterprise subscription
Go to your repository on GitHub.com
Navigate to Settings → Rules → Rulesets
Click "New ruleset" → "New branch ruleset"
Name: "Copilot Code Review", enable for default branch
Add rule: "Require code review from Copilot"
2.2

Create PR Using Copilot and MCP

Goal: Push changes and create a Pull Request using Copilot Chat.

Commit and push the problematic code:
git add backend/transfer-utils.ts
git commit -m "Add transfer utilities (WIP)"
git push origin feature/review-practice
▶ 💬 Create PR Prompt 
Create a pull request for the feature/review-practice branch to main.

First, analyze the changes using #get_changed_files, then:
1. Generate a descriptive title
2. Write a summary of changes
3. List any known issues or TODOs
4. Create the PR on GitHub

Use the GitHub MCP tools to create the actual PR.
2.3

Interact with Copilot's Review

Goal: Practice responding to and discussing Copilot's review comments.

💬
Example @copilot Replies:
Defending your choice: 
@copilot The console.log statements are intentional for this 
debugging phase. We'll remove them before release.
Asking for clarification: 
@copilot Can you explain why using strict equality is 
important here? What bugs could loose equality cause?
Requesting code suggestion: 
@copilot Can you show me the corrected version of 
this function with all your suggestions applied?
⚖️
Local vs PR Review
Aspect Local Review PR Review
When Before commit After push
Where VS Code GitHub
Trigger Manual Automatic (if configured)
Visibility Only you Team can see
Best For Quick feedback Team collaboration

Recommendation: Use both! Local review for quick fixes, PR review for team visibility.

🔑 Best Practices

  • Set up project-specific review instructions - reduces false positives
  • Shift-left with local review - catch issues before they reach PR
  • Use capable models (Claude Sonnet 4, GPT-4o) for better analysis
  • Don't ignore Copilot comments - address or justify them
  • Use @copilot mentions to discuss, not dismiss
  • Combine with human reviewers - Copilot augments, not replaces
