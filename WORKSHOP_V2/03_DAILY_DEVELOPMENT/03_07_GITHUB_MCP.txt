GITHUB MCP SERVER SETUP & USAGE
================================

WHAT IS GITHUB MCP?

The GitHub Model Context Protocol (MCP) server allows your AI assistant (Copilot) to directly interact with GitHub.
It can:
- Search and read repositories
- Manage issues and pull requests
- Push changes and create branches
- Analyze commit history

This bridge connects your coding environment directly to your GitHub workflow.

---

TASK 1: SETUP GITHUB MCP SERVER

Goal: Configure the GitHub MCP server to allow Copilot to access your GitHub data.

Prerequisites:
- GitHub Account
- Personal Access Token (PAT) with `repo` scope

Steps:
1.  **Generate a GitHub PAT:**
    -   Go to GitHub Settings -> Developer settings -> Personal access tokens -> Tokens (classic).
    -   Generate new token (classic).
    -   Select scopes: `repo`, `user`, `read:org`.
    -   Copy the token (you won't see it again!).

2.  **Configure the Server:**
    -   You need to add the server configuration to your MCP settings file (e.g., `~/.vscode/extensions/ms-vscode.copilot-mcp/config.json` or similar depending on your specific setup, or via the VS Code UI if available).
    -   Command to run: `uvx mcp-server-github` (requires `uv` installed) or `npx -y @modelcontextprotocol/server-github`.
    -   Environment Variable: `GITHUB_PERSONAL_ACCESS_TOKEN=<your-token>`.

    *Example Configuration (JSON):*
    ```json
    "github": {
      "command": "uvx",
      "args": ["mcp-server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..."
      }
    }
    ```

3.  **Restart VS Code / Reload Window** to apply changes.

Question:
-   How do you verify the server is running? (Hint: Ask Copilot "Can you list my recent issues?")

---

TASK 2: VERIFY CONNECTION & BASIC RETRIEVAL

Goal: Confirm the MCP server is working by retrieving data from GitHub.

Action:
Ask Copilot: "Please list the last 5 issues assigned to me in the 'github-copilot-workshop' repository."

Expected Output:
-   A list of issues with titles and numbers.
-   If it fails, check your PAT permissions and server configuration.

Experiment:
-   Try listing pull requests: "Show me open PRs in this repo."
-   Try listing branches: "What branches are active right now?"

---

TASK 3: REMOTE FILE INSPECTION

Goal: Read a file from a repository *without* cloning it locally.

Scenario: You need to check the `package.json` of a dependency or a related project to see its version.

Action:
Ask Copilot: "Read the contents of 'package.json' from the 'facebook/react' repository."

Questions:
-   Did it retrieve the file content?
-   Can you ask specific questions about it? (e.g., "What is the version in that file?")

---

TASK 4: SEARCH & CONTEXT GATHERING

Goal: Use GitHub search to find relevant code or discussions.

Action:
Ask Copilot: "Search for issues related to 'memory leak' in the 'nodejs/node' repository."

Follow-up:
-   "Summarize the solution proposed in issue #12345."

Why this matters:
-   You can debug errors by finding similar reports in upstream repositories without leaving your editor.

---

TASK 5: CREATE AN ISSUE (OPTIONAL)

Goal: Create a new issue directly from the chat.

Action:
Ask Copilot: "Create a new issue in this repository titled 'Bug: Login fails on Safari' with the body 'Steps to reproduce: 1. Open Safari. 2. Click Login. 3. Nothing happens.'"

*Note: Be careful not to create spam issues in public repos! Use your own sandbox repo for testing.*

---

TROUBLESHOOTING

-   **"Tool not found":** Ensure the MCP server is properly registered in the config file.
-   **"Authentication failed":** Check your PAT. It might be expired or lack the `repo` scope.
-   **"Rate limited":** GitHub API has limits. If you hit them, wait a while.

---

KEY LEARNINGS
-   MCP turns Copilot into an *agent* that can perform actions, not just generate text.
-   You can interact with remote repositories as easily as local files.
-   Context from issues and PRs can be pulled directly into your chat to solve problems.
